# 前台列印與後台協同操作增修

日期：2026-11-03　狀態：使用者已確認實作範圍

本文件更新 2026-10-24 的協同列表與送出設計中，關於預設條件、列印限制及單筆頁開啟方式的規則。

## 本機資料庫

參照 Supabase 專案 `tbulauezaixdjzdcqsem` 的五張 `heal_` 資料表，以現有 PostgreSQL 17 Docker 設定及 Drizzle migration 重建。沿用資料表、索引、外鍵、檢查約束與 RLS，不新增欄位，也不複製雲端問卷、使用者與登入紀錄。六種表單以現有 migration 建立初始設定；整合測試使用獨立的 `wjcch_test`。

2026-11-04 經使用者確認，本機主資料庫由 `healthcare` 原地更名為 `wjcch`，測試資料庫由 `healthcare_test` 更名為 `wjcch_test`，既有資料、資料表結構與 migration 紀錄保留。同步調整 `.env`、連線範例、Docker 初始化與測試預設值；Docker 容器、資料卷及本機帳號維持原設定。Supabase 專案名稱為 `wjcch`，雲端資料庫名稱仍為 `postgres`。

## 前台

- 成功送出後顯示「列印 / 另存 PDF」，在原畫面載入隱藏的原樣 A4 文件，待字型及圖片完成載入後直接開啟瀏覽器列印介面，省去新分頁預覽與第二次點擊。直接開啟列印網址時仍提供預覽工具列。
- 列印內容由伺服器重新讀取已送出的民眾資料，院所欄位留白。
- 須持有原裝置憑證，且在有效期限內、表單種類一致，才可存取。修改中、已作廢或憑證無效時不提供前台列印。

## 後台

- 首次進入：六種表單全選，只勾選「待院所確認」。`submitted` 僅變更顯示名稱，狀態流程不變。
- 不含數字的查詢字串依姓名部分比對，不分英文字母大小寫；含數字則維持身分證號部分比對及其正規化。LIKE 特殊字元視為一般文字。
- 輸入查詢內容時自動全選，清空後恢復原勾選。明確清空以 `filtered=1` 記在網址，避免重新整理後套回首次預設。
- 列表使用 `open` 網址參數開啟 modal；原篩選、排序、頁碼、捲動位置及尚未套用的欄位維持在背景。關閉後重新查詢更新列表。單筆直接網址仍可使用。
- 民眾填寫內容預設展開。所有狀態均提供列印；不改變確認送出、取消送出、作廢及復原流程。
- 關閉 modal 或列印前，等待院所區佇列中的自動暫存，再儲存最新內容。衝突或儲存失敗則停留編輯畫面，避免遺漏資料；列印頁只讀取成功存入的內容。
- 前台、後台列表與編輯視窗共用直接列印程序，取消列印後保留原畫面及條件；隱藏文件在列印結束後清除，載入失敗時顯示可重試的錯誤。
- 參考 CodePen `https://codepen.io/jcoulterdesign/pen/bNxeKY` 的齒輪動畫，使用本地 CSS 實作等待遮罩，包含載入、查詢、切頁、明確操作、設定儲存及 QR 圖檔產生。自動暫存維持局部提示。遵守減少動畫偏好。

## 民眾修改與防重送（使用者另行確認）

- 修改原表單時依既有案件編號送出，不以畫面上的狀態文字決定是否新增。狀態查詢的晚到回應不得影響正在修改的流程。
- 首次送出前產生固定 UUID，先保存在裝置，再送交伺服器並作為新案件編號。網路重試沿用相同 UUID；伺服器回傳原筆的實際時間與狀態。
- 伺服器使用交易層級 advisory lock 協調同一有效裝置、同一身分與同種類表單的並行建立請求，再鎖住既有資料列處理更新，不新增資料表或欄位。
- 暫存編號遺失時，只能憑原有效裝置憑證恢復唯一的相同身分、同種類未完成案件。身分證號本身不構成讀取或覆蓋授權。
- 已送出且內容相同的重試回傳原筆，內容不同須先退回修改。退回後再次送出更新同一筆，並以原送出時間辨識修改批次；上一輪的晚到請求不能覆蓋下一輪修改。
- 院所已填的適用資料及填寫人資訊保留；依新答案清除不再適用的隱藏欄位。原本未填院所區時仍保留空資料，讓首次開啟可正常帶入院所預設值。
- 已完成或作廢的舊案件不覆寫；新次填寫使用新編號。已成功的相同請求即使後來由院所完成，重試仍回傳原結果而不另建。
- 原有多份未完成資料不任選、不合併。無法唯一辨識時回報需洽櫃台確認；原案件及紀錄保留。
